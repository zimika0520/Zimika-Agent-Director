# AI视频执行层:从已确认剧本到可生成的镜头单元

本文件是模型无关的 AI 视频适配总规则。整体采用三层结构:

1. **原著忠实层**:事件索引、故事事实、决策台账、分集剧本——不受任何视频模型影响。
2. **AI剧本层**:`ai_shot_plan:E001`(AI分镜单元计划)+ 四类锚点——把剧本拆成视觉单元、动作起止状态、台词绑定、状态链、负面约束和每单元通用中文提示词,模型无关。**这一层是默认最终交付**;语义审查(`ai_video_boundary_review`)绑定在这一层。
3. **模型适配层(可选)**:仅当用户点名需要某平台的参数化任务包时启用——`model_capability_profile:<模型>` + `ai_video_execution_plan:E001:<模型>` 把已确认分镜单元按该模型能力打包并按平台格式编译;编译不重审语义。默认不生成任何模型专属产物。

Seedance 2.0 的接口事实见 [seedance-compatibility.md](seedance-compatibility.md);其他模型建立各自的能力档案,复用本文件全部纪律。

依据:《衷情无限》第一集逆向导演稿(48 个视觉单元实测)、《穿成炮灰庶女》60 集商用脚本拆解、斩神截图节选试验的执行包实践。样本数据只作参考基准,不冒充行业硬标准。

## 定位与解锁条件

- AI 视频执行层是**一等交付物**,不是全剧文学交付后的附件。项目规格 `delivery_target` 为 `ai_video` 或 `both` 时,它进入默认交付范围。
- 按集解锁:某集剧本通过对应 `episode_boundary_review` 且该集台词声音表、涉及角色/场景的锚点已就绪,即可生成该集执行包;不必等全剧完稿。
- 执行层仍然只做下游适配:不得改变人物、事件、因果、关系、知情范围、世界规则或结局;不生成图片、不提交视频任务。

## 上游资产预算(在改编圣经与全剧地图阶段执行)

资产失控是 AI 视频一致性和成本的头号风险(样本教训:116 种地点写法、37 场"百姓若干"、85 场外景)。资产约束必须在写剧本**之前**锁定,不能等提取阶段再归并:

- 改编圣经登记 `asset_budget`:主场景数上限、核心角色数、单集出场角色数上限、群演策略、内外景倾向。数值由项目商定,默认建议仅作起点:每集新增主场景 ≤1、单集有台词角色 ≤4。
- 每个主场景规划母版空间+2—4 个子区域+可复用机位轴线(如"书案正反打轴线"),写进场景锚点;全剧地图为每集标注复用哪些场景资产、新增哪些。
- 群演场面在大纲阶段就拆成固定套路:1 个交代规模的大全景 + 2—3 个可复用群众中景 + 1—2 个固定反应近景 + 主角与关键对手正反打;不写"百姓若干"就完事。
- 高成本要素(大规模室外、战争、水火、动物、婴儿、复杂动作戏)在地图阶段标记,并给出低成本替代表达(声音+反应、局部特写、空镜+画外)。

## 锚点制品(纯文字,一次定义,处处引用)

四类锚点是执行层的规范制品,用 `project_tool.py register-artifact` 登记为 `style_anchor`、`character_anchor:C001`、`scene_anchor:L001`、`prop_anchor:P001` 形式的制品键(上游分别绑定改编圣经、角色提取表、场景提取表、道具服装台账),存放在 `10_AI视频执行包/`;只含文字描述与既有素材引用,不含生成的图片:

- **风格锚点**(全剧一份):画风、比例、色彩基调、光线原则、禁止事项(字幕/Logo/水印默认禁止)。它编译成全剧统一提示词头。
- **角色锚点**(每核心角色一份):年龄段、体型、发型发色、五官特征、标志服装(分套编号)、标志道具、绝不改变项。角色出现的每个生成单元都必须注入其外形锁摘要,不能只在第一单元写。
- **场景锚点**(每主场景一份):母版空间描述、子区域、日/夜/天气版本、固定机位轴线、不可改变的建筑特征、同场统一光线色调。
- **道具锚点**(承担剧情功能的道具):外观、尺寸、材质、可辨识细节、状态版本(完好/破损/染血)。

锚点从已确认剧本与四类提取表派生,受同样的内容边界约束:外形细节属于表达层,可以补;但暗示新事实的设定(伤疤讲故事、徽记表身份)必须有原著依据或获批新增。

## AI分镜单元计划 `ai_shot_plan:E001`

AI剧本层的权威制品,规范 JSON,登记后先过 `ai_video_boundary_review:E001` 前置门禁再确认。每个视觉单元必须包含:

- `unit_id`(`SP-E001-U001` 形式,全剧稳定)、`sequence`、`scene_id`
- `narrative_task`(单一叙事任务)、`action_start` / `action_end`(动作起止,供首尾帧接力)
- `duration_seconds`(切点级时长,>4 秒必须写 `over_4s_rationale`)
- `source_refs`(原著事件依据)、`decision_ids`(改编决策)
- `characters_on_screen`:每名出场角色带 `character_id`、`anchor_ref`(锚点制品键+版本号)和 `appearance_lock` 外形锁摘要
- `scene_anchor_ref` / `prop_anchor_refs`(带版本号)
- `dialogue`(cue_id + lip_sync 标记;lip_sync 说话人每单元 ≤1)
- `sound`、`negative_constraints`(单元级负面约束,非空)
- `generation_strategy`(生成策略档位)
- `state_chain`:`chain_id` + `enter`/`exit` 结构化角色状态(位置/朝向/服装/持有道具/伤势/知情范围);同链上一单元 `exit` 必须与下一单元 `enter` 完全一致

- `prompt_text`(推荐):本单元的通用中文提示词——外形锁+动作+镜头+环境+声音+台词原文+负面约束编译成一段可直接粘贴到任意视频平台的文字,不含任何模型专属参数(时长档位、模式名、分辨率等)。通用提示词让分镜计划本身即是可用交付,无须模型适配层。

计划级字段:`hard_blocks`(本集必须阻断清单,非空)、`asset_budget`(从圣经复制的预算,超预算须写 `over_budget_note` 或返修)。台词 cue 必须逐条且仅一次覆盖。以上全部由 `project_tool.py` 在 approve 时自动校验;锚点引用过期版本(存在更新的已确认版本)会被拒绝,锚点更新后受影响计划自动标记失效。

## 模型能力档案 `model_capability_profile:<模型>`(可选,仅按用户点名启用)

模型适配层的约束来源,一个模型一份,规范 JSON:`model_family`、`provider_model_id`、`capability_snapshot`(status/checked_at/官方 source_urls)、`capabilities`(task_duration_seconds 区间、ratios、resolutions、generate_audio、lip_sync、max_reference_images、supports_first_frame/first_last_frame/continuation、max_clear_speakers、input_modes)。未核实的能力写 `null` 并在 notes 说明,不得猜测;校验器按档案而不是硬编码值约束执行计划。

## AI视频执行计划 `ai_video_execution_plan:E001:<模型>`(可选,仅按用户点名启用)

模型适配层产物:把已确认 `ai_shot_plan` 的全部单元(每个恰好消费一次)打包成生成任务并编译提示词。每个任务:`task_id`、`source_unit_ids`、`duration_seconds`(必须在能力档案区间内)、`generation_mode`(必须在档案 input_modes 内)、`reference_asset_ids`(text_to_video 不绑素材;continuation 同链续接可免绑)、`clear_speakers`(≤档案上限)、结构化 `prompt`(style_ref/subject/action/camera/environment/negative 必填)+ 编译后 `prompt_text`、`chain` 连续链。`execution_policy` 固定 `generate_images: false`、`submit_video_requests: false`。同一集换模型 = 换能力档案重新编译,不动分镜计划、不重审语义。

## 视觉单元与节奏纪律

区分两个层级:**生成任务**(一次模型调用,时长受能力快照约束)与**视觉单元**(一个镜头/切点)。一个生成任务内部可以包含多个切点,用"镜头1/切"描述。

- 每个视觉单元只做一件事:一个叙事任务、一种主要机位或运镜、一个信息变化。
- 节奏基准(样本实测,允许项目调整):对白驱动的漫剧,视觉单元多落在 1—4 秒;超过 4 秒的单元必须写明内部持续变化的信息(位移、上肩、表情转变、推镜)。判断标准是"画面信息是否持续变化",不是机械截断。
- 每个生成任务的切点数建议 1—3 个;切点越多,模型内部时序越不可控。台词密集段优先用"说话者近景 / 听者反应 / 手部与证据特写 / 空镜"四类镜头交替消化。
- 开场纪律:每集前 5 秒必须出现异常、冲突或类型错位,不做世界观解释;世界观用闪回蒙太奇或高信息量单帧,不用长篇口述。
- 信息增量检查:约每 15 秒必须有新信息或局势变化;连续两个单元信息静止即返修。
- 集尾纪律:最后一个单元用未回答的问题、突变的人物距离或骤停动作卡断,不新抛设定。

## 表演词汇纪律

生成模型无法稳定执行抽象表演词。剧本层即禁止,执行层再拦一次:

- 禁用:眼神幽深、气场全开、气势压住全场、一瞬间明白、眼底闪过X、意味深长。
- 必须写成可生成动作:视线看向谁/何物、嘴角是否抬起、手部具体动作(握紧、松开、停顿)、身体前倾或后退、停顿多久、对方是否避开视线、镜头推近到什么景别。
- 每个单元的可见动作必须有明确起点和终点状态,供首帧/尾帧接力使用。

## 台词、口型与声音策略

- 一个生成任务内只允许一名角色清晰对嘴;其余说话人转画外(OS)、背面、远景或反应镜头承接。
- 长台词按语义拆分到多个单元,不删词、不改词、不重复;拆分点写在台词声音表 cue 上,每条 cue 逐条且仅一次覆盖。
- 每个单元登记声音三层:对白 cue、环境声、音效点(如针落、门轴);BGM 与字幕默认后期独立处理。
- 传闻、判断、误解、未知不得用客观画面认证;提示词中明确禁止闪回认证或越权揭示。

## 生成策略与提示词契约

`generation_strategy` 是编排层字段,描述这段画面按什么成本档位生产;它与执行计划里的接口层字段 `generation_mode`(能力快照定义的取值,如 `text_to_video`/`first_frame`/`continuation`/`multimodal_reference`)并存,不互相替代。映射约定:`tail_frame_chain` → `generation_mode: continuation`(与上一单元同链,无需预登记参考素材);`image_to_video`/`first_frame` → 首帧类模式,必须绑定已提供素材;`static_frame`/`partial_animation` 属后期与局部动态方案,生成任务仍按能力快照声明模式。每个生成任务必须声明 `generation_strategy`,不同镜头用不同成本档位,不全部按最贵方式生成:

- `static_frame`:单帧+后期运镜(高信息量说明画面、UI、界面)。
- `partial_animation`:锚图局部动态(口型、眨眼、发丝)。
- `image_to_video` / `first_frame`:首帧构图+动作终点。
- `tail_frame_chain`:上一任务尾帧作首帧,同场连续动作。
- `text_to_video`:无可用锚定素材时的冷启动。

提示词按结构化字段组装,不写成一团散文:

```json
{
  "style_ref": "style_anchor 编译头",
  "subject": [{"character_id": "C001", "appearance_lock": "外形锁摘要", "wardrobe": "服装套编号"}],
  "action": "起点状态 → 可见动作链 → 终点状态",
  "camera": "一种主要机位/运镜;多切点时逐镜列出",
  "environment": "场景锚点摘要 + 日夜天气 + 光线色调",
  "dialogue": [{"cue_id": "Q-...", "speaker": "C001", "lip_sync": true}],
  "sound": ["环境声", "音效点"],
  "negative": ["全局禁止项", "本单元专属禁止项"],
  "duration_seconds": 4
}
```

- 全局负面约束(风格锚点)+ 单元级负面约束(本单元的"必须阻断":不得露出的角色、不得认证的传闻、不得提前泄露的信息)都要落到具体单元,不只写在文档头部。
- 编译后的自然语言提示词与结构化字段同存;结构化 JSON 是校验权威。

## 链式生成与重试台账

- 同场景内优先尾帧接力;场景或时间硬切处必须重新锚定(场景锚点+角色锚点),不跨场景续链。
- 首帧专用模式与多模态参考素材遵守当次能力快照的互斥规则。
- 建立 `generation_retry_ledger`:记录失败单元、失败现象(错词、串声、外形漂移、轴线跳变)、修复动作(改提示词/换策略/重锚定)与生效版本。只重生当前任务,不得反过来改相邻单元的故事事实迁就模型;提示词修复经验回写锚点或全局头,让后续单元受益。

## HTML 故事板(人工检查界面)

分镜计划确认后,用确定性渲染器生成单文件 HTML 故事板供人工可视化检查(只读展示,不改状态、不调模型、不生成图片):

```bash
python3 <技能目录>/scripts/project_tool.py render-storyboard <项目目录> E001
# 输出 10_AI视频执行包/E001_故事板.html(render_storyboard.py 也可直接调用)
```

内容:节奏时间轴(单元按时长绘制、场景固定配色、5秒钩子线与15秒刻度、超4秒单元标示)、逐单元卡片(任务/动作起止/人物外形锁悬浮/台词与对嘴标记/负面约束/通用提示词一键复制)、锚点资产表、必须阻断清单、切点分布与总时长偏差。支持深色模式与打印。分镜计划出新版本后重跑命令即可,规范数据始终以项目 JSON 为准。

## 执行层节奏质检清单

执行包确认前逐项核对,结论写入执行层边界报告的补充段:

1. 前 5 秒是否兑现异常/冲突,而非解释设定。
2. 每单元是否单一叙事任务、单一主运镜、明确起止状态。
3. 超 4 秒单元是否写明持续信息变化;连续静止信息单元是否已返修。
4. 每 15 秒信息增量是否成立。
5. 台词 cue 是否逐条且仅一次覆盖;每任务是否只有一名清晰对嘴者。
6. 出场角色是否全部注入外形锁;场景切换是否重新锚定。
7. 单元级负面约束是否覆盖本集"必须阻断"清单。
8. 集尾是否以钩子单元卡断。
9. 资产使用是否在预算内;新增资产是否有登记理由。
10. 高成本镜头是否给出生成策略与降级替代。

校验通过只代表文字执行层达到结构、节奏、追溯和边界要求;真实模型输出效果未实测,不得写成"已验证成片"。
