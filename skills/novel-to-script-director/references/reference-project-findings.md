## Toonflow：已核实机制

以下文件位于上述固定 tree：

- `src/routes/novel/event/generateEvents.ts`：选中章节先把 `eventState` 重置为 `0`、清空旧事件，再异步生成事件；每章成功写 `1`，失败写 `-1` 并保存 `errorReason`。
- `src/utils/cleanNovel.ts`：逐章读取原文，通过受限并发生成事件摘要，并按章发出成功或失败结果。
- `src/routes/novel/addNovel.ts` 与 `src/routes/novel/updateNovel.ts`：初次导入的错误字段存在 `errReason`/`errorReason` 命名不一致；修改原文不会自动使既有事件失效或重新提取。
- `src/agents/scriptAgent/tools.ts`：虽然读取 `eventState`，返回给 Agent 时只拼接事件文本，没有阻断处理中或失败章节。
- `data/skills/script_agent_decision.md` 与 `src/agents/scriptAgent/index.ts`：将流程分为故事骨架、改编策略、单集剧本；骨架与策略产出后调用独立监督角色审核。
- `data/skills/script_execution_skeleton.md`：骨架读取章节事件，记录故事核、人物弧、分集、删减和钩子等规划信息。
- `data/skills/script_execution_adaptation.md`：改编策略读取事件与骨架，记录正面原则、负面边界、删减理由和世界观呈现方式。
- `data/skills/script_execution_script.md`：单集稿只读取当前集对应规划、原著事件与原文，并可读取上一集用于衔接。
- `data/skills/script_agent_supervision.md`：监督角色重新读取制品和依据，输出分级问题清单；审核本身不直接改稿，由用户决定修复或继续。

这些文件同时包含大量特定产品经验和视听生产要求，例如固定台词语速、固定批量上限、固定角色数量、固定付费点比例、秒级节奏、构图、转场、AI 图像或视频适配。仓库本身没有证明这些数值是行业统一标准，本插件不把它们设成硬门禁。已核实后端中执行 Agent 主要输出 XML，而显式写入如何闭环仍不清楚，也不把“输出 XML”当成可靠提交协议。

### 采纳

1. 原著先按可定位单元建立事件索引；每个单元保留处理状态与失败原因，未完成单元不能被静默忽略。
2. 把“原著事实”“改编决策”“全剧分集”“单集剧本”分层，避免写单集时重新发明全局结构。
3. 明确记录保留、压缩、合并、调序、删除和桥接新增的来源、理由、落点与影响。
4. 在全剧地图和试写门禁使用与起草分开的审核轮次；审核只报问题和证据，不静默改已确认稿。
5. 单集顺序写作，只加载当前集、上一集结束状态、下一集关键走向和相关原著片段。

### 不采纳

- 固定 `150 字/分钟`、固定场长、固定正文长度或固定批量集数。
- 把三幕、单线、核心人物上限、付费点百分比或某种情绪配比当成所有项目必须遵守的标准。
- 为追求节奏牺牲核心因果，或把样本经验包装成确定性商业结论。
- 镜号、景别、机位、运镜、焦段、构图、转场、单镜时长、分镜表以及图片/视频提示词。

## Huobao：已核实机制

固定提交中的关键文件：

- `skills/script_rewriter/SKILL.md`：规定统一场头、动作自然段和对白格式，明确禁止景别、角度和运镜。
- `backend/src/agents/tools/script-tools.ts`：`episodes.content` 保存原始内容，`episodes.scriptContent` 保存改写稿；工具读取原文，模型完成改写，再直接保存改写字符串。
- `skills/extractor/SKILL.md` 与 `backend/src/agents/tools/extract-tools.ts`：提取前读取项目全部已有角色/场景及当前集关联；角色按姓名精确匹配，场景按“地点＋时间”精确匹配，复用后关联当前集。
- `backend/src/agents/index.ts` 与 `backend/src/agents/skills.ts`：不同 Agent 只加载对应 Skill；`episodeId`、`dramaId` 通过工具闭包注入，不让模型自由填写数据库主键。

仓库没有完整的小说解析、章节自动分集、全剧规划、版本依赖、原著追溯、连续性或全剧交付门禁。角色同名会直接合并非空字段，场景只做精确字符串匹配；重新提取不会清理已经失效的旧关联，保存循环也没有事务。Skill 提到道具，但所核实保存工具没有道具通道。

### 采纳

1. 原始内容与改编稿分开保存，任何阶段不得覆盖原文件。
2. 当前集提取前先读取全剧规范实体，优先复用稳定 ID，再建立本集关联。
3. 别名、同名不同人、同地点不同空间版本不能静默合并；冲突必须进入人工确认清单。
4. 文学剧本使用统一场头、动作、对白和声音标记，并禁止导演镜头语言。

### 不采纳

- 直接覆盖唯一 `scriptContent`，不保存版本、依赖和审批。
- 仅凭姓名或“地点＋时间”完全相等自动合并。
- 把“改写增量 20%—30%”或“每场 30—60 秒”设为硬标准。
- 提取未经剧本验证的外形、氛围和图片提示词。
- 分镜、图片、宫格、配音、TTS、视频生成、FFmpeg 合成及其状态字段。

## 对本插件的落地要求

- `SourceEventIndex`：记录全部原著单元的稳定 ID、定位、处理状态、错误或排除理由和事件；只有全部单元成功或经说明排除后才能进入事实库。
- `AdaptationDecisionLedger`：每条改编操作绑定原著单元、目标集、理由、受保护事实和连续性影响；桥接新增必须单独标记，不得伪装成原著事实。
- 三层内容边界：核心原则是“可以增加表达，不得擅自增加故事事实”。全剧地图、批次大纲和每集剧本均先登记 `awaiting_approval`，再由精确绑定当前版本的边界报告前置审核；不是从参考项目复制的文字规则。
- 可追溯人工门禁：边界结论区分 `passed`、`approved_addition`、`suspected_overreach`、`blocked`；主要新增必须回查用户授权，自动判断明确不保证百分之百正确。
- 阶段审核：全剧地图和试写稿必须经历“起草 → 独立审核 → 返修 → 用户确认”，严重问题没有关闭或明确豁免时不得过门；内容事实越界不能用普通质检豁免替代用户授权。
- 实体归一：角色、地点、道具服装使用稳定 ID、别名和冲突清单；当前集提取只能复用或提出合并建议，不能静默覆盖规范记录。
- 交付边界：最终只交付制作就绪文学剧本及文字提取表；导演拆镜及全部视听生产属于下游。
