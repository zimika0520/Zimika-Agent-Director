## 定义

“制作就绪”表示编剧工作已经完成：制作团队可以直接提取人物、场景、道具、服装、台词和声音，并进入导演拆镜；不需要返回编剧补剧情、人物动机、动作因果或跨集连续性。

它不表示可以跳过导演、美术、配音、剪辑或直接自动成片。用户要求 Seedance 兼容时，另行生成纯文字执行层；该层不改变本制作就绪剧本包，也不生成图片或视频。

## 提取规则

制作提取开始前，全部当前分集剧本必须已确认，且每集都有精确绑定当前版本、结论为 `passed` 的已确认 `episode_boundary_review`。四类提取表与连续性台账的 `generated_from` 和制品 `depends_on` 必须同时绑定这些剧本和对应边界报告；不能少绑、错绑或沿用旧版本。

### 角色

- 一个稳定角色 ID 贯穿全剧。
- 分清原著事实、批准的改编设定和当前阶段状态。
- 记录每集/每场出场、服装伤势、知情范围与关系变化。
- 不编写图片提示词或未经确认的外形细节。
- 提取前读取全剧已有角色；同名、别名或身份冲突先进入人工归一，不静默覆盖稳定 ID。

### 场景

- 同一地点的不同文字写法归并到稳定地点 ID。
- 记录空间分区、入口出口、固定陈设、日夜版本和可互动元素。
- 写清当场进入/离开状态，不能只列地点名称。
- 地点、日夜和内外景必须与剧本场头一致；同一稳定地点 ID 的名称与空间定义不能互相冲突。

### 道具与服装

- 只列真正参与剧情或连续性的物件。
- 记录出现、持有、转移、损坏、变化和最终去向。
- 服装变化必须有时间或剧情依据。

### 台词与声音

- 按集号、场号、角色与类型逐条提取。
- 台词、VO、OS、环境声和关键音效分型。
- 保留原文和语境，不在提取时改词或新增内容。

## 第四门禁检查

- 所有计划集数都有已确认剧本。
- 原著事件索引没有失败或静默缺失单元；改编决策台账不存在待确认项。
- 全剧地图、每份批次大纲和每集剧本都曾先登记 `awaiting_approval`，并分别通过精确绑定当前版本的内容边界报告；没有用后补报告绕过前置门禁。
- 内容边界发现只能是 `passed`、`approved_addition`、`suspected_overreach` 或 `blocked`；交付时不得残留 `suspected_overreach` 或 `blocked`。
- 所有 `passed` 项都有明确原著依据；所有 `approved_addition` 都能回查改编决策和用户变更授权记录。自动报告明确说明判断并非百分之百可靠。
- 未经授权新增/改变主要人物、身份、能力、核心关系，改变动机、关键事件、因果、世界规则、结局性质，提前泄密，以及无原著依据的主要新增，一律阻断。
- 心理外化、对白重写、衔接、时间压缩、动作补全、群众/环境反应和原著事件戏剧化展开均有原著追溯，且没有改变故事事实。
- 全剧规划和试写审核报告精确绑定当前版本，且没有未关闭阻断项。
- 交付校验和打包都显式提供预期总集数，不以“当前找到几集”代替全剧计划。
- 每集通过结构校验与语义质检。
- 四类制作提取表齐全，可回查全部当前剧本及对应分集内容边界报告。
- 连续性台账覆盖全部剧集，没有阻断问题。
- 连续性台账使用规范 JSON 顶层 `records` 逐场覆盖；每条包含 `character_states`、`item_states`、`relationship_state`、`knowledge_state`、`unresolved_threads`、`storyline_progress`、`relative_time` 和 `end_state`。
- 规范 JSON 质检报告精确绑定当前剧本、四类提取表和连续性台账，无未处理阻断项，或记录了用户明确豁免。
- 目标时长有配音实读或明确标注尚未实测，不能虚报。
- 交付包不含内部审批备注、图片提示词或导演分镜字段。
- Seedance 文字执行计划如有，保存在独立兼容层并单独通过内容边界报告；不把它伪装成文学剧本，也不把未生成的参考素材列为已完成资产。
- 交付清单记录每个文件的版本与 SHA-256 散列。
