# AI导演全自动智能体编排设计

日期：2026-07-30

状态：设计已确认，运行时实现已落地；2026-08-03按宿主能力修订为单层编排并冻结接口

## 1. 问题

当前AI导演已经具备来源分片、滚动摘要、批次状态和断点恢复，但这些能力主要控制项目材料，不控制Codex会话本身。

长篇项目在单个会话中持续执行时，会不断积累：

- 原著片段；
- 插件说明与阶段参考；
- 工具调用和输出；
- 剧本、审核与返修讨论；
- 多个批次和分集的历史状态。

因此，项目虽然可以在上下文中断后恢复，单个执行会话仍会逐渐接近上下文上限。允许并发智能体也不足以解决问题：如果所有详细结果继续回流同一个主会话，主会话仍会膨胀。

## 2. 目标

1. 用户始终停留在一个主会话中。
2. 主任务使用宿主能力直接创建、等待和关闭一次性工作智能体，不要求用户手工建立新任务。
3. 重任务使用不继承历史的短生命周期智能体。
4. 主会话只接收简短状态、人工门禁和恢复结果，不接收原著全文或完整制品。
5. 保持现有项目状态、内容边界、审批、版本、散列和交付门禁。
6. 不降低原著依据、剧本质量、独立审核、连续性或制作就绪标准。
7. 同一任务连续失败两次后停止，不无限重试、不跳过失败项。

## 3. 非目标

- 不建设独立后台服务。
- 不引入数据库、消息队列或常驻守护进程。
- 不复制一套新的项目阶段状态机。
- 不实现复杂Token估算器或通用分布式调度平台。
- 不允许相邻分集并行写作。
- 不允许为避免上下文压力而缩短必要原著、跳过审核或自动降级模型。
- 不改变AI导演不生成图片、不提交视频、不调用配音或剪辑接口的边界。

## 4. 方案选择

### 方案A：主会话直接管理一次性工作智能体

主会话是唯一监督者。工作智能体只返回不超过任务契约限制的短结果信封，完整内容写入候选文件；主会话不接收完整原著或完整制品。当前Codex宿主只在主任务暴露`multi_agent_v1`，因此这是本设计采用的方案。

### 方案B：主会话、协调智能体、工作智能体两级编排

当前宿主不会把`multi_agent_v1.spawn_agent/wait_agent/close_agent`传给子智能体，两级嵌套无法落地。本方案停用，不再尝试通过上下文继承或提示词传递不存在的工具。

### 方案C：外部运行服务

可以获得最强的任务队列、租约和监控能力，但会显著增加安装、维护和故障面，不符合当前插件的轻量定位。

## 5. 总体架构

```text
用户
  ↕
主会话 / 监督者
  ↓ 创建，不继承上下文
一次性工作智能体
  ↓ 写文件
候选输出与结果清单
  ↓
project_tool.py 校验、合并和单一状态写入
  ↓
检查点或人工门禁
```

### 5.1 主会话

负责：

- 接收用户需求与确认；
- 读取项目摘要；
- 调用CLI生成当前逻辑业务片段的不可变任务包；
- 直接创建、等待和关闭一次性工作智能体；
- 将活动宿主任务ID回传CLI；
- 接收工作智能体的简短结果信封；
- 调用CLI校验、登记并写入检查点；
- 在人工门禁处暂停并展示需要用户决定的内容；
- 用户确认后规划下一逻辑业务片段。

主会话禁止：

- 读取完整原著；
- 读取工作智能体完整输出；
- 直接生成分集剧本、来源分析或制作提取；
- 让工作智能体继承主会话历史；
- 绕过CLI手工修改项目状态。

### 5.2 逻辑业务片段

`coordinator_slice`字段为兼容现有任务包保留，只表示一个自然业务片段：

- 一个来源窗口；
- 一集剧本及其独立审核；
- 一组制作提取；
- 一个批次收尾。

它不是智能体层级，不拥有会话，也不创建工作智能体。主任务按该字段组织任务、检查点和恢复范围。

### 5.3 工作智能体

每个工作智能体只完成一个原子任务，例如：

- 一个来源分析分片；
- 一集文学剧本；
- 一份独立内容边界审核；
- 一类制作提取；
- 一份AI分镜计划；
- 一份AI视频内容边界审核。

工作智能体使用`fork_context: false`，只读取任务包允许的输入路径，只写自己的候选目录。完成后只返回结果清单路径和简短状态，然后立即关闭。

### 5.4 CLI单一写入器

`project_tool.py`继续作为唯一机器权威，由主任务调用，负责：

- 根据现有`project_state.json`计算下一业务片段；
- 生成不可变任务包；
- 校验候选输出路径、输入版本、散列和结构；
- 执行确定性合并；
- 登记候选制品为`awaiting_approval`或适用状态；
- 更新现有项目状态；
- 保存运行检查点；
- 拒绝重复幂等键和非法并发写入。

Python CLI不直接调用模型、不创建智能体，也不实现第二套内容工作流。

## 6. 薄运行目录

项目内新增不参与交付包的目录：

```text
.ai-director/runtime/
├── run.json
├── tasks/
├── results/
├── candidates/
└── checkpoints/
```

用途：

- `run.json`：当前逻辑业务片段、活动宿主任务、失败次数和最近检查点；
- `tasks/`：不可变任务包；
- `results/`：工作智能体结果清单；
- `candidates/`：尚未通过CLI验收的候选文件；
- `checkpoints/`：任务完成、失败或宿主任务失联时的恢复信息。

`project_state.json`只增加精简的`agent_runtime`摘要，不保存完整队列和日志。运行状态不得复制或取代现有阶段、制品、审批和批次权威。

## 7. 任务包契约

```json
{
  "schema_version": 1,
  "run_id": "RUN-20260730-001",
  "task_id": "TASK-B01-E001-SCRIPT-001",
  "task_type": "episode_script",
  "batch_id": "B01",
  "episode_id": "E001",
  "attempt": 1,
  "input_refs": [
    {
      "artifact_key": "batch_outline:B01",
      "version": 1,
      "path": "05_批次大纲/B01_大纲_v1.json",
      "sha256": "..."
    }
  ],
  "allowed_read_paths": [],
  "allowed_write_directory": ".ai-director/runtime/candidates/TASK-B01-E001-SCRIPT-001",
  "acceptance_command": "validate-script",
  "supervisor_mode": "single_layer_host",
  "state_write_policy": "supervisor_only",
  "host_task_id": null,
  "host_task_status": "unbound",
  "recovery_state": "none",
  "return_max_chars": 1000
}
```

任务包必须：

- 锁定输入版本和散列；
- 明确读写路径；
- 明确任务类型与范围；
- 明确验收命令；
- 声明主任务单层监督和宿主工作智能体绑定状态；
- 禁止工作智能体自行扩大原著范围；
- 禁止复用旧任务的会话历史。

## 8. 结果信封契约

```json
{
  "schema_version": 1,
  "task_id": "TASK-B01-E001-SCRIPT-001",
  "status": "completed",
  "result_manifest_path": ".ai-director/runtime/results/TASK-B01-E001-SCRIPT-001.json",
  "candidate_output_paths": [
    ".ai-director/runtime/candidates/TASK-B01-E001-SCRIPT-001/E001_文学剧本.md"
  ],
  "error_code": null
}
```

聊天返回只允许包含：

- `task_id`；
- 成功、失败或阻塞状态；
- 结果清单路径；
- 错误代码；
- 是否需要重试。

完整分析、剧本、审核和提取内容必须写入文件，不得粘贴回主会话。

## 9. 自然业务片段

### 9.1 来源窗口片段

```text
规划当前B批次来源窗口
→ 创建同构来源分片智能体
→ 分片写入独立候选目录
→ CLI确定性合并
→ 独立智能体判断ready_for_batch或needs_more_source
→ CLI登记滚动进度
→ 主任务关闭已完成的工作智能体
```

`ready_for_batch`后不得继续读取下一窗口。`needs_more_source`必须包含具体来源缺口。

### 9.2 单集剧本片段

```text
创建剧本智能体
→ 写候选文学剧本
→ CLI结构校验
→ 创建独立边界审核智能体
→ 登记剧本和审核为待确认版本
→ 更新连续性候选
→ 进入人工门禁或规划下一逻辑业务片段
```

剧本智能体和审核智能体不得为同一个会话。

### 9.3 制作提取片段

已确认剧本可以并行创建：

- 角色提取智能体；
- 场景提取智能体；
- 道具服装提取智能体；
- 台词声音提取智能体。

它们写不同候选文件。全局实体ID归一、连续性合并和正式登记必须串行。

### 9.4 批次收尾片段

批次收尾串行完成：

- 连续性快照；
- 批次质检；
- 制作就绪复核；
- 批次交付审核；
- 批次交付包。

完成后主任务关闭全部已完成工作智能体并展示批次结果。

## 10. 上下文隔离

1. 主会话创建工作智能体时固定使用`fork_context: false`。
2. 每个工作智能体只读取任务包与允许路径。
3. 工作智能体只返回精简结果信封，完整内容写文件。
4. 主会话按自然业务片段轮换一次性工作智能体，不长期保留工作会话。
5. 不使用任意Token或字节阈值决定业务逻辑；自然业务边界本身就是轮换点。
6. 若运行时报告上下文截断或压缩异常，当前工作智能体立即停止，保存可用文件结果，并由主任务依据检查点创建全新工作智能体恢复。

## 11. 质量保障

上下文隔离不得降低质量：

- 工作智能体获得当前任务所需的完整原著片段，不用过度压缩摘要替代原著；
- 关键输入全部带版本和散列；
- 创作和审核使用独立智能体；
- 相邻分集保持串行；
- 全局人物ID、时间线、连续性和项目状态保持单一写入；
- 现有三层内容边界门禁和四道确认门禁保持不变；
- 候选文件未通过CLI校验不得登记；
- 不因上下文或容量问题跳过审核、缩短原著、降低交付标准；
- 工作智能体默认继承主任务配置的模型，不自动切换为更弱模型；
- 模型切换只能由用户明确授权。

## 12. 人工门禁

以下情况必须停止自动派发并回到主会话：

- 项目规格确认；
- 新增B批次；
- 内容边界出现`blocked`或`suspected_overreach`；
- 需要用户授权改编新增；
- 剧本、批次或最终交付确认；
- 同一任务连续失败两次。

暂停流程：

```text
停止派发
→ 等待可安全完成的当前任务
→ CLI保存检查点
→ 主任务关闭相关工作智能体
→ 主会话展示确认内容
→ 用户确认
→ 规划下一逻辑业务片段并创建新的工作智能体
```

子智能体不能代替用户确认，也不能把“继续”解释为新增内容授权。

## 13. 失败与恢复

### 13.1 工作任务失败

首次失败：

- 保留失败结果清单；
- 候选文件不得登记；
- 使用同一输入版本和散列创建全新工作智能体；
- `attempt`增加为2。

第二次连续失败：

- 当前运行状态改为`blocked`；
- 停止全部相关任务；
- 保存恢复检查点；
- 返回主会话完整报告。

禁止在同一失败智能体中无限重试。

### 13.2 宿主工作智能体失联

- 主任务每次规划都传入全部仍活动的宿主工作智能体ID；
- `planned/running`任务只有在宿主ID仍活动、存在有效结果或存在有效检查点时才能复用；
- 三者都不存在时，当前attempt标记为`abandoned/recovery_required`并写检查点；
- 主任务使用原幂等键创建attempt 2，不复用旧工作会话；
- 第二次仍失联时标记`blocked`并停止；
- 旧attempt晚到结果不得登记，避免同一幂等键产生两个有效结果。

### 13.3 幂等

```text
idempotency_key =
task_type
+ 输入制品版本与散列
+ batch/episode/source范围
+ contract_version
```

同一幂等键只能产生一个有效结果。重试可以保留失败记录，但不能生成两个正式版本。

## 14. 最小CLI表面

只增加三类薄命令，避免建设第二套Runtime：

```text
plan-agent-slice
accept-agent-result
show-agent-runtime
```

- `plan-agent-slice`：从现有项目状态生成下一自然业务片段和不可变任务包；
- `accept-agent-result`：验证结果清单、候选文件和输入绑定，然后调用现有登记逻辑；
- `show-agent-runtime`：输出当前逻辑业务片段、宿主任务绑定、阻塞原因、最近检查点和下一步。

这些命令复用现有`show`、`register-artifact`、`approve`、`set-stage`、校验和交付函数，不复制阶段流转。

## 15. 运行环境要求

全自动模式只要求主任务拥有以下宿主能力：

- 创建智能体；
- 等待智能体；
- 向智能体发送修正指令；
- 关闭智能体；
- 创建不继承父会话上下文的智能体。

不要求子智能体继续创建智能体。若主任务缺少这些能力，插件必须明确报告“当前运行环境不支持全自动智能体编排”，不得静默退化成单会话长流程。

## 16. 兼容性

- 旧项目无需迁移现有制品；
- 第一次启用时按当前`project_state.json`生成运行目录和检查点；
- 已确认制品不重做；
- 已登记章节分析按幂等键复用；
- 关闭全自动模式不会改变现有项目制品；
- `.ai-director/runtime/`不进入最终交付包。

## 17. 验收标准

1. 一个长篇项目可跨至少三个逻辑业务片段连续推进，主会话不读取完整原著或完整工作制品。
2. 每个工作智能体只完成一个任务，并在结果验收后关闭。
3. 主任务直接创建、等待和关闭工作智能体，不创建第二级协调层。
4. 工作智能体使用不继承历史的上下文。
5. 剧本生成和内容边界审核来自不同智能体。
6. 相邻分集不能并发写作。
7. 任何工作智能体都不能直接修改`project_state.json`。
8. 同一任务首次失败可由全新智能体重试，第二次连续失败停止自动链。
9. 人工门禁期间不创建新的工作智能体。
10. 重试不能产生两个有效制品版本。
11. 现有内容边界、审批、连续性和交付校验结果不因编排层而放宽。
12. 不自动降低模型能力、不裁剪必要原著、不跳过独立审核。

## 18. 实施边界

本设计只定义自动智能体编排和上下文隔离。实施时应优先：

1. 增加运行目录和任务/结果契约；
2. 增加三个薄CLI命令；
3. 更新SKILL与工作流，要求主任务直接使用内部多智能体工具；
4. 完成来源窗口片段；
5. 完成单集剧本与独立审核片段；
6. 完成制作提取与批次收尾；
7. 最后验证旧项目恢复、人工门禁和连续失败停止。

不得同时重构与本目标无关的内容工作流、交付格式或AI视频契约。

## 19. 阶段三接口冻结

自2026-08-03起，下列全局编排接口作为当前兼容基线冻结。后续简介模式或其他入口只能调用，不得复制、绕过或静默改变其语义：

- 运行时入口：`startup-preflight`、`plan-agent-slice`、`accept-agent-result`、`show-agent-runtime`。
- 任务包核心字段：`task_id`、`task_type`、`scope`、`attempt`、`max_attempts`、`idempotency_key`、`input_refs`、`allowed_read_paths`、`allowed_write_directory`、`acceptance_command`、`context_inheritance`、`scheduling_mode`、`scheduling_key`、`state_write_policy`、`supervisor_mode`、`host_task_id`、`host_task_status`、`recovery_state`。
- 结果信封核心字段：`task_id`、`idempotency_key`、`status`、`candidate_output_paths`、`error_code`和五类耗时加`error_class`的`telemetry`。
- 幂等键继续由任务类型、业务范围、输入版本与散列及契约版本决定；重试只增加`attempt`。
- `planned/running`任务只有活动宿主ID、有效结果或有效检查点之一存在时才能复用；否则进入`abandoned/recovery_required`，第二次失联进入`blocked`。
- 同一幂等键只能有一个有效结果；旧attempt晚到结果必须拒绝。
- 默认并发2并受`max_parallel_tasks`与`service_capacity`共同限制；独立任务可并行，串行任务、同调度键和项目状态写入不得并行。
- `project_state.json`保持项目锁、进程锁和原子替换的单一写入语义。
- 429、流式断开、上下文超限继续使用各自恢复动作；显式失败或宿主失联均最多两次attempt。
